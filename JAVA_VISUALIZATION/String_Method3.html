Arrays, Regular Expressions, and Memory Interning

1. Converting a String to a Character Array

Because Strings are objects in Java, you can't access their characters using array syntax like s[0]. If you need to loop over every individual character easily, converting it to an array is the best approach.

  • toCharArray(): Unpacks the entire string and creates a new char[] array in heap memory containing every character in sequence.

2. Validating Text (Regular Expressions)

Instead of manually looping through characters to see if a string is a valid number, email, or password, Java allows you to use Regular Expressions (Regex) via the matches() method.

  • matches(regex): Returns true only if the entire string matches the given pattern.
  • In our code, "[0-9]+" means: "Does this string consist of digits from 0-9, and is it at least 1 character long (+ means one or more)?"

3. The String Pool and `intern()`

Java optimizes memory by keeping a special area in the Heap called the String Pool. When you type literal strings in quotes like "Hello", Java puts them in the pool.

  • Scanner.nextLine() builds the string dynamically at runtime, so s lives in standard Heap memory (e.g., address 0x222), not the pool.
  • new String(s) explicitly forces Java to create a brand new, separate object in the Heap for s2 (e.g., address 0x444).
  • s2.intern() checks the String Pool for the value. Since it isn't there, it adds it to the pool and returns the new pool reference (e.g., 0xAAA).
Result: When checking (s2.intern() == s), we are comparing the Pool reference (0xAAA) to the original Heap reference (0x222). They point to different memory locations, so it returns false!
