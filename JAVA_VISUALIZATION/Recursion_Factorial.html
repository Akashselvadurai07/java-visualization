Documentation Java Recursion — Detailed Notes

1. What is Recursion?

Recursion is a programming technique where a method calls itself to solve a problem. In simple words: a method repeatedly calls itself with a smaller or simpler input until it reaches a stopping condition.

A recursive method must have two important parts:

  • Base Case → Stops the recursion
  • Recursive Case → Calls the same method again
static void function() {
    // Base Condition

    // Recursive Call
    function();
}

2. Why Do We Need Recursion?

Some problems naturally have a repetitive or self-similar structure. Examples include:

  • Factorial
  • Fibonacci
  • Sum of numbers
  • Power calculation
  • Reverse a number/string
  • Palindrome
  • Binary Search
  • Tree & Graph traversal
  • Divide and conquer algorithms
  • Backtracking

3. Base Case

The base case is the condition that stops the recursive calls.

static void print(int n) {
    if (n == 0) { // Base Case
        return;
    }
    System.out.println(n);
    print(n - 1);
}

Without a base case, the method continues calling itself forever.

4. Recursive Case

The part where the method calls itself is called the recursive case. (e.g., print(n - 1);). The value becomes smaller: 5, 4, 3, 2, 1, 0, eventually making the base case true.

5. Simple Recursion Example

class Main {
    static void print(int n) {
        if (n == 0) {
            return;
        }
        System.out.println(n);
        print(n - 1);
    }
    public static void main(String[] args) {
        print(5);
    }
}

Output: 5, 4, 3, 2, 1

Flow: print(5) → print(4) → print(3) → print(2) → print(1) → print(0) → return

6. How Recursion Works Internally

Java uses the Call Stack to manage method calls. Each method call is stored in the stack. When print(0) reaches the base case, it returns, and then the previous method calls return one by one.

STACK
┌─────────────┐
│ print(0)    │
├─────────────┤
│ print(1)    │
├─────────────┤
│ print(2)    │
├─────────────┤
│ print(3)    │
└─────────────┘

7. Recursion Has Two Phases

Phase 1 — Going Down: Recursive calls keep happening (5 → 4 → 3 → 2 → 1 → 0).

Phase 2 — Coming Back: After reaching the base case, the methods return (0 → 1 → 2 → 3 → 4 → 5). This is why the position of statements like System.out.println() matters.

8. Print Before Recursive Call

static void print(int n) {
    if (n == 0) return;
    System.out.println(n); // Executes on the way down
    print(n - 1);
}

Output: 5, 4, 3, 2, 1

9. Print After Recursive Call

static void print(int n) {
    if (n == 0) return;
    print(n - 1);
    System.out.println(n); // Executes on the way back up
}

Output: 1, 2, 3, 4, 5

10. Factorial Using Recursion

Recursive Formula: n! = n × (n - 1)!
Base case: 0! = 1

static int factorial(int n) {
    if (n == 0) {
        return 1;
    }
    return n * factorial(n - 1);
}

11. Fibonacci Using Recursion

Formula: F(n) = F(n - 1) + F(n - 2)
Base cases: F(0) = 0, F(1) = 1

static int fibonacci(int n) {
    if (n == 0) return 0;
    if (n == 1) return 1;
    return fibonacci(n - 1) + fibonacci(n - 2);
}

12. Sum of First N Natural Numbers

Formula: sum(n) = n + sum(n - 1)

static int sum(int n) {
    if (n == 0) return 0;
    return n + sum(n - 1);
}

13. Power Using Recursion

Formula: power(a, n) = a × power(a, n - 1)

static int power(int a, int n) {
    if (n == 0) return 1;
    return a * power(a, n - 1);
}

14. Reverse a Number Using Recursion

One approach carries the reversed value as an additional parameter.

static int reverse(int n, int rev) {
    if (n == 0) return rev;
    return reverse(n / 10, rev * 10 + n % 10);
}
// Call: reverse(1234, 0) -> Returns 4321

15. Recursion vs Iteration

Recursion Iteration
Method calls itself Loop repeats
Uses call stack Usually uses less stack memory
Can make tree/divide-and-conquer problems easier Often simpler for straightforward repetition
Can have function-call overhead Usually lower overhead
Needs a base case Needs loop condition
May cause StackOverflowError Usually doesn't have recursive stack growth

16. Recursion and Stack Memory

Every recursive call creates a new stack frame. factorial(5) occupies memory until the base case is reached, after which frames are removed one by one.

17. Stack Overflow

If recursion never reaches a base case, calls continue indefinitely until Java throws a StackOverflowError.

18. Types of Recursion

18.1 Direct Recursion

A method directly calls itself.

18.2 Indirect Recursion

One method calls another method, which eventually calls the first method. (e.g., A() calls B(), B() calls A()).

19. Tail Recursion

A recursive call is the last operation performed by the method. (e.g., calling print(n - 1) with no further calculations).

20. Non-Tail Recursion

If operations happen after the recursive call (like multiplication in return n * factorial(n - 1)), it is non-tail recursion because it must return before calculating the final result.

21. Multiple Recursion

A method makes more than one recursive call (like Fibonacci), creating a branching recursion tree.

22. Recursion Tree

Visualizing Fibonacci shows how the same values are repeatedly calculated, highlighting why simple recursion for Fibonacci is inefficient:

fib(4)
├── fib(3)
│   ├── fib(2)
│   │   ├── fib(1)
│   │   └── fib(0)
│   └── fib(1)
└── fib(2)
    ├── fib(1)
    └── fib(0)

23. Time Complexity

  • Factorial: Time: O(n), Space: O(n) (stack space).
  • Fibonacci (Simple): Time: O(2^n), Space: O(n).

24. Recursion Template

static returnType function(parameters) {
    if (baseCondition) {
        return baseValue;
    }
    return function(smallerInput);
}

25. Three Questions to Ask When Solving Recursion

Whenever you see a recursion problem, ask:

  • Question 1: What is the base case? (e.g., n == 0)
  • Question 2: What is the smaller problem? (e.g., n - 1)
  • Question 3: How do I combine the answer? (e.g., return n * factorial(n - 1);)
