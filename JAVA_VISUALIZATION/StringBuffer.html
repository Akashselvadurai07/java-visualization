Mutability: Why use StringBuffer?

In Java, standard String objects are immutable. If you want to modify a string 1,000 times, Java forces you to create 1,000 brand new objects in Heap memory, which is incredibly slow and wastes RAM.

StringBuffer solves this! It acts like a mutable (changeable) container. You can add, insert, or delete characters directly inside it without creating new objects in memory. (Note: Unlike StringBuilder, StringBuffer is synchronized, which makes it thread-safe for concurrent programming!)

Core StringBuffer Methods

  • append(text): Glues text onto the very end. Extremely fast compared to str1 + str2 in a loop.
  • insert(index, text): Pushes new text into the middle of the string at the exact index, shifting existing characters to the right.
  • replace(start, end, text): Overwrites a chunk of characters between two indices with new text. The new text doesn't even have to be the same length as the chunk you removed!
  • delete(start, end): Simply removes the characters between the given indices.
  • reverse(): Flips the entire string backwards instantly. Doing this manually with a standard String requires an expensive loop.
  • setCharAt(index, char): Replaces just a single character at a specific position.

Extracting the Result

Because a StringBuffer isn't technically a String, you can't pass it into methods that require a String parameter. Once you are entirely done building your text, you call toString().

Memory Check: Notice in the animation how sb keeps updating the same Heap object (0x333). But when toString() is called, Java takes a snapshot of the final text and allocates a brand new, immutable String object in the Heap (0x444) for result!
